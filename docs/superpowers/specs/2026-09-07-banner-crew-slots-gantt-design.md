# Слоты баннерщиков на заказе и Гант занятости

**Date:** 2026-09-07  
**Status:** Approved in chat · revised 2026-09-08 (shared site install, BASE hidden)  
**Repo:** TwentyView (BrandingTwentyView)  
**Related:** [поставщики в уточнении](./2026-08-24-suppliers-type-sections-evening-digest-design.md), [справочники phase 1](./2026-07-28-reference-directories-phase1-design.md)

## Problem

1. Когда на позиции стоит тип «Баннера», в уточнении выбирают, кто едет. Это один поставщик на позицию, без времени.
2. Баннерщики едут **на заказ**, не на отдельную позицию. Время монтажа у бригады своё и не равно `opportunity.loadDate`.
3. Один человек может в том же заказе быть **на объекте** и **на базе** — это разные интервалы.
4. Нет экрана, где видно, кто уже занят.

## Goals / non-goals

| In | Out |
|----|-----|
| Слоты на сделке: человек + место (объект/база) + начало + конец | Замена колонки «Уточнение» |
| Чип на строке сделки и модалка заказа | Подряд, плёнка, прочие типы |
| Гант занятости баннерщиков | Справочник «Выездной персонал» как источник людей |
| Предупреждение при пересечении; сохранить можно | Жёсткий запрет сохранить конфликт |
| Люди = поставщики категории `BANNERA` | Раскидка людей по позициям в v1 |
| | Несколько слотов одного места в одном заказе |
| | Drag-and-drop на Ганте |
| | Telegram-пачка по слотам (вечерний пинг остаётся на `loadDate`) |
| | BrandingTeamApp / PWA исполнителей |

## Decisions (locked)

| Topic | Choice |
|-------|--------|
| Scope | Только позиции/заказы с типом «Баннера» |
| Люди | Объект `supplier`, `category === BANNERA` |
| Где время | На заказе, не на позиции |
| Место | `SITE` «на объекте» / `BASE` «на базе»; оба допустимы у одного человека в одном заказе |
| Интервал | Начало и конец; не точка и не «занят весь день» |
| Кардинальность | Не больше одного слота на тройку заказ + человек + место |
| Уточнение | Без изменений; редкая привязка человека к позиции остаётся там |
| Вход | Чип на **строке сделки**, если есть хотя бы одна позиция `tip === BANNERA` |
| Конфликт | Предупреждение + цвет на Ганте; запись не блокируем |
| Экран занятости | Гант, не табель и не «Гант как единственный редактор» |
| Неделя Ганта | Пн–вс, `Europe/Moscow` |
| Черновик | Нет начала или конца → в модалке есть, на Ганте и в занятости нет |
| Отмена сделки | Стадия `OTMENA`: слоты не удаляем, занятость не считаем |
| Смежные интервалы | Конец A = начало B → **не** конфликт |
| Новый человек из модалки | Не создаём поставщика; только существующие активные `BANNERA` |

## Architecture

```
Deals board (parent row)
  has BANNERA line item? → BannerCrewChip → BannerCrewModal(opportunityId)
       CRUD bannerCrewSlot { opportunity, supplier, location, startsAt, endsAt }

Gantt page (nav, like Оклейщики)
  rows = BANNERA suppliers (active, plus anyone with a slot in range)
  bars = complete slots whose opportunity.stage !== OTMENA
  click bar → same BannerCrewModal

Уточнение / SupplierCombobox
  unchanged
```

Паттерн страницы как у Оклейщиков: `front-component` + `page-layout` STANDALONE + `navigationMenuItem`. Объект слотов — источник правды; сырой index view объекта нужен для отладки, в левом меню пользователю показываем **Гант**, не таблицу слотов.

Сущности заводить через `yarn twenty dev:add` (object, fields, view, frontComponent, pageLayout, navigationMenuItem). Все UUID — v4.

## Data model

### Object: `bannerCrewSlot`

- `nameSingular`: `bannerCrewSlot` · `namePlural`: `bannerCrewSlots`
- `labelSingular`: `Слот баннерщика` · `labelPlural`: `Слоты баннерщиков`

| Field | Type | Notes |
|-------|------|--------|
| `opportunity` | RELATION M2O → warehouse `opportunity` | Заказ |
| `supplier` | RELATION M2O → `supplier` | Человек |
| `location` | SELECT `SITE` / `BASE` | Объект / база |
| `startsAt` | DATE_TIME, nullable | Начало, смысл в Москве |
| `endsAt` | DATE_TIME, nullable | Конец, смысл в Москве |

Имя записи (`name`) — служебное, можно собирать как «{supplier} · {location}» в UI, не как ручное поле менеджера.

### Invariants (код + UI, не обязательно DB unique)

1. Одна запись на `(opportunityId, supplierId, location)`. Повтор create → обновить существующую или отказать с тостом и не плодить дубли.
2. Если оба конца заданы: `startsAt < endsAt`. Равенство и инверсия — ошибка, не писать.
3. UI пикера: `supplier.category === 'BANNERA'` и (`isActive` или уже есть слот на этом заказе).

### Occupancy

Слот **занимает** человека, если:

- оба конца заполнены;
- `startsAt < endsAt`;
- связанная сделка существует и `stage !== 'OTMENA'`.

Пересечение двух занимающих слотов одного `supplierId`:

```
startsAtA < endsAtB && startsAtB < endsAtA
```

Считается и внутри заказа (база ∩ объект), и между заказами.

## Board UI

### Chip

Место: родительская строка сделки, рядом с колонкой даты (`loadDate`). Чип есть, если у сделки есть хотя бы одна позиция `tip === BANNERA` (стадия позиции не важна). Иначе чипа нет.

| Состояние | Подпись (смысл) |
|-----------|-----------------|
| Нет слотов | «Баннерщики» |
| Люди есть, ни одного полного интервала | Имена + «без времени» |
| Есть полные слоты | Имена и короткие интервалы, база помечена словом «база» |
| Есть конфликт занятости | Тот же текст, предупреждающий цвет чипа (токены доски, не радуга) |

Клик — модалка этого `opportunityId`. Мобильная доска: тот же чип, модалка на весь экран.

### Modal

Заголовок — имя сделки. Дата `loadDate` показана как подсказка, в слоты сама не копируется; дату слота можно поставить в тот же календарный день одной кнопкой/префилом.

Тело:

1. Список активных баннерщиков. Человек **на заказе**, если есть хотя бы одна запись слота на эту сделку (черновик или полная).
2. Включить человека без времени → создать черновик **`SITE`** с пустыми концами (по умолчанию «едет на объект»). Блок базы пустой, пока его не заполнят — строки `BASE` нет.
3. У человека на заказе — два независимых блока: **На объекте**, **На базе**. В каждом: дата, время начала, время конца. Заполнить базу → upsert слота `BASE`. Очистить блок места → удалить слот этого `location`.
4. Пересечение с другими занимающими слотами этого человека — жёлтый текст и имя конфликтующего заказа. Сохранение не блокируется.
5. Снять человека с заказа → удалить **все** его слоты по этому `opportunityId`. Колонку уточнения на позициях не трогать.

Валидация блока места: оба конца пусты — черновик, ок; заполнен только один конец — ошибка «укажи начало и конец»; оба заданы — `startsAt < endsAt`.

Нет прав на create/update/delete слотов — тост, UI откатывается к серверу.

## Gantt

Новая страница в меню (подпись вроде **Баннерщики**), canvas на весь виджет, без внутреннего скролла-ловушки вне оси времени.

- **Строки:** поставщики `category === BANNERA` с `isActive`. Неактивные — только если в выбранной неделе есть занимающий слот.
- **Ось X:** текущая неделя пн–вс Москва; кнопки предыдущая/следующая неделя.
- **Полоса:** один занимающий слот. `SITE` и `BASE` разными тихими цветами (категорийный green баннера как акцент объекта; база — нейтральный/второй оттенок, не фиолетовый SaaS).
- **Конфликт:** пересекающиеся полосы одного человека — конфликтный цвет (как warning чипа), оба интервала.
- **Клик по полосе:** та же модалка заказа.
- Пустая строка = свободен на этой неделе.

Не в v1: drag полос, зум как в MS Project, фильтр «только этот заказ», отдельный day-view.

Десктоп — основной. Мобильный Гант: горизонтальный скролл недели, без отдельного layout.

## Errors and edge cases

| Case | Behavior |
|------|----------|
| `endsAt <= startsAt` | Не сохранять, ошибка в блоке |
| Пересечение | Warning, сохранить |
| Поставщик скрыт (`isActive: false`) | Старые слоты живы; в пикере новых заказов нет |
| Сделка `OTMENA` | Слоты в CRM; чип на отменённой строке по общим фильтрам доски; **занятость/Гант игнор** |
| Позиции баннера сняли тип | Чип пропадает, когда не осталось ни одной позиции `tip === BANNERA` (стадия позиции не важна); слоты заказа **не** автоудалять |
| Opportunity удалили | Слоты: onDelete SET_NULL или CASCADE — предпочесть CASCADE, чтобы не висели сироты на Ганте |
| Supplier удалили | SET_NULL недопустимо для занятости → CASCADE или запрет удаления, пока есть слоты. Предпочесть **SET_NULL запрещён, onDelete RESTRICT/не удалять из UI поставщиков** (как сейчас скрытие через `isActive`) |

Realtime: слоты в реестр query keys доски/Ганта, инвалидация как у `okleykaSalaryEntry`.

## Testing

- Юнит: пересечение интервалов (внахлёст / касание концами / вложенность / разные люди).
- Юнит: «макс. один слот на место»; чип виден iff есть `BANNERA`.
- Юнит: черновик не занимает; `OTMENA` не занимает.
- После `yarn twenty apply`: чип на сделке с баннером; модалка база+объект; Гант недели; два заказа внахлёст — warning и красные полосы, оба слота на месте.

## Rollout

Только TwentyView. `yarn twenty apply` на local, затем staging/prod по обычному циклу. Бэкфилл из уточнения **не** делаем: старые имена на позициях остаются в `supplier` связи позиции, слоты заводятся руками.

## Revision 2026-09-08 — только монтаж на объекте

Временно **не показываем «на базе»** в модалке, чипе и Ганте. Поле `location=BASE` в CRM не удаляем; UI его игнорирует. Снятие галочки с человека удаляет **все** его слоты заказа (включая старые BASE).

**Общее время монтажа:** один интервал на заказ. В модалке сверху: дата+время начала и дата+время конца (две даты, ночь через полночь допустима). На «Сохранить» те же `startsAt`/`endsAt` пишутся в SITE-слот каждого отмеченного человека.

**Люди:** галочка = на этом монтаже. Снять галочку или «Убрать» — человек пропадает со сделки сразу. Всех заранее не отмечаем.

**Время:** обычные поля, не селекты часов/минут; минуты любые (`23:50`). Конец может быть на следующих календарных сутках. Кнопка «Как у сделки» ставит обе даты в день `loadDate`.
