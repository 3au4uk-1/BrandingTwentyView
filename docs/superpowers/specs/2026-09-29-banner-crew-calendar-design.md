# Календарь баннерщиков и адрес из Tony

**Date:** 2026-09-29  
**Status:** Approved in chat  
**Repos:** BrandingTwentyView (календарь, поле), crmparserv2 (запись адреса и разовый прогон)  
**Related:** [слоты и гант](./2026-09-07-banner-crew-slots-gantt-design.md)

## Problem

Гант баннерщиков показывает людей и только те заказы, где слот уже заполнен началом и концом. Сделка с позицией «Баннера» без слота на экране не появляется. Адреса объектов парсер забирает из Tony в свою базу и в сделку Twenty не пишет, поэтому на экране бригады адреса нет.

Нужен один оперативный экран: все сделки с баннером, что закрыто бригадой и что нет, без данных других направлений.

## Goals / non-goals

| In | Out |
|----|-----|
| Календарь сделок с позицией «Баннера» | Фреза, печать, производство |
| Неделя по умолчанию, переключение на месяц | Штатный календарь Twenty и отдельные записи «сделка на день» |
| Гант людей по кнопке с этого экрана | Второй пункт меню для ганта |
| Адрес объекта на сделке, перезапись из Tony | Адрес компании, ручной адрес как источник правды |
| Разовый допис адреса уже синкнутым сделкам | Полный ресинк сделки ради адреса |

Спека слотов и ганта от 2026-09-07 остаётся в силе: модалка, объект `bannerCrewSlot`, конфликты, чип на доске. Этот документ меняет только вход в экран «Баннерщики» и добавляет адрес.

## Decisions (locked)

| Topic | Choice |
|-------|--------|
| Кто на экране | Сделка с хотя бы одной позицией `tip === BANNERA` |
| Отмена | Стадия `OTMENA` на календарь не попадает |
| Закрыто | В слотах сделки есть хотя бы один человек. Время для этого не нужно |
| Уточнение на позиции | Не смотрим. Источник людей — только слоты |
| Куда класть день | Дни слота с началом и концом. Нет такой даты — дата загрузки. Нет обеих — полоса «Без даты» |
| Карточек в день | Одна на сделку, даже если слотов несколько |
| Длинный слот | Каждый календарный день от начала до конца включительно, Europe/Moscow |
| Время на карточке | Время слотов этого дня. Нет времени слота — время загрузки |
| Адрес | Текст на сделке. Непустой адрес Tony при синке затирает поле, включая ручную правку. Пустой адрес Tony поле не стирает. Не-Tony синк поле не трогает |
| Старые сделки | Один прогон дописывает только адрес. Слепок заказа из‑за этого сам не меняется |
| Экран | Пункт «Баннерщики» открывает календарь. Кнопка переключает на текущий гант и обратно |

## Architecture

```
Пункт меню «Баннерщики»
  страница: режим календарь | режим гант
  календарь читает сделки, позиции BANNERA, слоты, адрес, дату загрузки
  дни и подписи времени считает чистая функция
  клик по карточке → существующая BannerCrewModal

crmparser, сбор сделки для Twenty
  если источник tony и адрес непустой → пишет opportunity.address
  пустой адрес и не-tony → ключ адреса в патч не кладёт

разовый прогон
  синкнутые tony-сделки с непустым адресом → patch только address
```

Новых объектов нет. Слоты остаются источником правды о людях и интервалах.

## Calendar

Неделя — понедельник–воскресенье, `Europe/Moscow`. Стрелки листают неделю или месяц. «Сегодня» открывает период, в котором лежит сегодняшний день, и запоминает его выбранным. Переключатель недели и месяца не сбрасывает день, на который смотрят.

Месяц — сетка с понедельника. Дни соседних месяцев — пустые ячейки для выравнивания, карточек там нет, клик по ним ничего не делает.

Выбранный день: клик по карточке или по пустой ячейке текущего месяца его запоминает. Клик по карточке ещё и открывает модалку бригады.

Гант — тот же экран, кнопка туда и обратно. Отдельного пункта меню нет. Из режима недели гант открывается на показанную неделю. Из месяца — на неделю выбранного дня. Выбранного дня нет: неделя, где лежит сегодня, если сегодня в этом месяце; иначе первая неделя показанного месяца.

### Какие дни получают карточку

День — календарная дата `Europe/Moscow` у начала и у конца слота, и каждая дата между ними. Конец раньше начала или заполнен только один край: слот на дни не раскладывается и ведёт себя как слот без даты.

На каждый такой день — одна карточка сделки. Люди и время на ней только из слотов, которые покрывают этот день.

День даты загрузки — календарная дата поля `loadDate` в `Europe/Moscow`.

Слот без даты своих дней не рисует. Человек из него попадает на карточку даты загрузки. Если этот день уже есть из датированного слота, второго дня нет: человек добавляется на существующую карточку, время карточки остаётся от датированных слотов.

Датированных слотов нет совсем — одна карточка на дате загрузки, на ней все назначенные и время загрузки.

Нет ни одной даты слота и нет даты загрузки — карточка в полосе «Без даты» над календарём. Время пустое. Люди, если они есть, видны. Полоса есть и в неделе, и в месяце.

Сделка без людей и с датой загрузки — одна карточка на этой дате, список людей пустой. Это и есть «не закрыто».

### Время

Часы в 24-часовом виде, `HH:MM`.

| День относительно слота | Подпись |
|-------------------------|---------|
| Начало и конец в этот день | `10:00–18:00` |
| Первый день более длинного слота | `с 10:00` |
| Последний день | `до 18:00` |
| День строго между | `весь день` |

Несколько слотов в один день схлопываются в один интервал: от самого раннего начала до самого позднего конца. Подпись «весь день» перекрывает часы. Дыры между интервалами не показываются.

Карточка только из‑за даты загрузки показывает время загрузки. Нет и его — строка времени пустая.

### Карточка

Неделя, полная карточка:

- название сделки
- время
- адрес, или пустая строка, если адреса нет
- кто назначен в этот день
- поле «позиции»: имена позиций `tip === BANNERA` только по наведению

Месяц, одна строка: название и метка, есть ли на этой карточке люди. Отдельного слова «закрыто» нет: людей нет — сделка на этой карточке не закрыта. Адрес, время, люди и позиции — по наведению на строку.

Клик в обоих режимах открывает ту же модалку, что чип на доске реализации.

## Address

Поле сделки: текст, имя `address`, подпись «Адрес». Заводится через `yarn twenty dev:add field` на объекте сделки. UUID v4.

Пишет crmparser в том месте, где собирается патч сделки для Twenty (`buildOpportunityInput`):

1. Источник сделки — Tony и строка адреса после обрезки пробелов непустая → в патч кладётся `address`.
2. Иначе ключ `address` в патч не входит. Уже записанный адрес не стирается, сделка не из Tony не меняется.
3. Сравнение «надо ли обновлять сделку» учитывает адрес, когда ключ в патче есть. Другой непустой адрес из Tony затирает и ручную правку.

Адрес уже входит в слепок заказа Tony. Смена адреса в Tony сама проводит сделку через обычный синк. Сделки, у которых слепок не менялся, адрес в Twenty не получат.

Разовый прогон, один раз после выкладки поля:

- берутся сделки парсера с `twenty_id`, источник Tony, адрес после обрезки пробелов непустой;
- в Twenty обновляется только `address`;
- пустой адрес, не-Tony и ошибка одной сделки прогон не останавливают и другие поля не трогают;
- повторный запуск с тем же адресом ничего больше не меняет.

## Errors

Список сделок или слотов не загрузился — на экране ошибка, не пустая неделя. Пустой адрес не прячет сделку. Слот с одним краем или с концом раньше начала не рисует свой диапазон.

## Units

| Unit | Does | Depends on |
|------|------|------------|
| Раскладка дней | Из слотов и даты загрузки делает дни, людей, подпись времени, полосу «Без даты» | Ничего экранного |
| Страница «Баннерщики» | Рисует неделю и месяц, переключает гант, открывает модалку | Раскладка, существующие слоты и модалка |
| Поле `address` | Хранит адрес объекта на сделке | — |
| Патч сделки | Кладёт непустой адрес Tony в синк | Поле `address` |
| Разовый прогон | Дописывает адрес старым сделкам | Поле `address`, база парсера |

## Testing

Раскладка дней, без экрана:

- слот на несколько дней даёт карточку на каждый день и подписи `интервал`, `с …`, `до …`, `весь день`;
- несколько слотов в один день — одна карточка, «весь день» перекрывает часы;
- человек без даты садится на дату загрузки и не плодит второй день, если день уже есть;
- нет дат вообще — полоса «Без даты»;
- `OTMENA` на календарь не попадает;
- слот с одним краем или с концом раньше начала ведёт себя как слот без даты.

Адрес:

- непустой адрес Tony записывается и затирает старый;
- пустой адрес и сделка не из Tony поле не трогают;
- сравнение сделки видит изменение адреса;
- разовый прогон меняет только `address`.
