## Problem

После первой итерации:

1. Печать и фреза — это расходы **сделки** (`rashodPechat`, `rashodFrezerovka`), а не позиции; текущая таблица считает их по позициям.
2. Оклейку нужно вводить **на сделке**, а не на позиции.
3. Продажа позиции должна считаться как **Сумма × Кол-во** (Сумма = цена за единицу).
4. Нужна панель людей (имя, часы, ставка) с фондом ЗП; введённая оклейка по сделкам вычитается из фонда.
5. Отчётный период — **половина месяца** (1–15/16/17 и остаток), день-граница меняется от месяца к месяцу.
6. Автоматизация: копирование людей из прошлого периода, авто-распределение остатка, подсказка доли при вводе, автозаполнение ставки.

## Goals

1. Экономика на уровне **сделки**: `маржа = (продажа − печать − фреза − оклейка) / продажа`.
2. Новое CURRENCY-поле `rashodOkleyka` на `opportunity`; редактируется только со страницы «Оклейщики».
3. Новый объект CRM `okleykaSalaryEntry` — записи людей по отчётным периодам.
4. Фильтр: месяц + сегмент «Весь месяц / 1-я половина / 2-я половина» + редактируемый день-граница (по умолчанию 15).
5. Панель ЗП: люди, фонд, раскидано, остаток; копирование из прошлого периода; автоставка по имени.
6. Кнопка «Распределить остаток» + подсказка «по продаже ≈ N ₽» при вводе оклейки.

## Non-goals

- `rashodOkleyka` **не** входит в `rashodItogo` / маржу «Реализации» / `rashodVyezdnayaKomanda`.
- Никаких CRM workflow — вся математика на странице.
- Спец-роли/права на объект зарплат — стандартные.
- Navigation menu item для `okleykaSalaryEntry` не создаём (страница «Оклейщики» — основной UI; index view создаём для служебного доступа).
- Позиционное поле `stoimostOkleyki` больше не используется страницей; определение поля остаётся (удаление/миграция — отдельным решением после применения схемы).

## Отчётные периоды

- `splitDay` — день-граница, по умолчанию **15**, редактируется в фильтре (clamp 10–25), НЕ персистится (v1).
- 1-я половина: `1 … splitDay`; 2-я половина: `splitDay+1 … конец месяца`.
- Режимы фильтра: `month` (весь месяц), `half` (полупериод), `range` (произвольный, только просмотр сделок).
- Сделки в период: по `loadDate` (fallback `closeDate`) — как сейчас.
- Записи ЗП периода: `periodStart[eq]` + `periodEnd[eq]` точным совпадением. В режиме `month` — обе половины (две группы в панели). В режиме `range` панель ЗП отключена (подсказка «выберите месяц или полупериод»).
- «Предыдущий период» = последний период, который **закончился до** начала текущего: записи с `periodEnd < dateFrom`, группировка по (periodStart, periodEnd), берём группу с максимальным `periodEnd` (при равенстве — максимальный `periodStart`). Работает при любых днях-границах.

## Формулы

Позиция: `unitPriceRub = currencyToRub(amount)`, `effectiveQty = kolichestvo > 0 ? kolichestvo : 1`, `saleRub = unitPriceRub × effectiveQty`.

Сделка (group):

```
saleRub    = Σ saleRub позиций
printRub   = currencyToRub(deal.rashodPechat)      // read-only
frezaRub   = currencyToRub(deal.rashodFrezerovka)  // read-only
okleykaRub = deal.rashodOkleyka → number | null    // null = не задано (для распределения)
costRub    = printRub + frezaRub + (okleykaRub ?? 0)
profitRub  = saleRub − costRub
marginPct  = saleRub > 0 ? profitRub / saleRub × 100 : null
```

Итоги страницы — суммы по сделкам. Позиции показывают только Кол-во · Цена · Продажа.

Фонд ЗП: `fundRub = Σ (hours × rateRub)` по записям выбранного периода (в month — обе половины).  
`spentRub = Σ (okleykaRub ?? 0)` по сделкам периода. `remainderRub = fundRub − spentRub` (зелёный ≥ 0 / красный < 0).

Подсказка при вводе оклейки: `hintRub = fundRub × dealSaleRub / Σ saleRub всех сделок периода` (null, если продажи нет или фонд 0/панель выключена). Показ «по продаже ≈ 12 400 ₽».

Распределение остатка: цели = сделки периода с `okleykaRub == null || okleykaRub === 0` и `saleRub > 0`. Каждой: `remainderRub × saleRub / Σ saleRub целей`, округление до рубля, разница округления — самой крупной цели. Перед массовой записью — подтверждение (`confirm`) с числом сделок и суммой. Если остаток ≤ 0 или целей нет — кнопка disabled с подсказкой.

## Панель людей (top-right)

- Ширина ~320px, справа от таблицы; на узких экранах — под шапкой.
- Строка: имя · часы · ставка · сумма; инлайн-редактирование часов/ставки; удаление (крестик + confirm не нужен, объём маленький — но удаление только своей строки, без bulk).
- Добавление: имя (datalist из имён прошлых периодов), часы, ставка; при вводе известного имени ставка автозаполняется из последней записи этого человека (если поле ставки ещё пустое/не тронуто).
- Итоги: Фонд · Раскидано · Остаток.
- Кнопка «Из прошлого периода»: копирует записи предыдущего периода в текущий (часы = 0, ставки сохраняются); дизейбл, если в текущем периоде уже есть записи, или предыдущий пуст. В режиме month кнопка у каждой половины.
- Оптимистичные обновления не обязательны: объём маленький, допустим invalidate после мутаций.

## Acceptance criteria

1. Поле `rashodOkleyka` (opportunity) и объект `okleykaSalaryEntry` + index view применяются `yarn twenty apply` без ошибок (или зафиксирован Windows-блокер как в v1).
2. Продажа позиции = цена × кол-во (кол-во ≤ 0 → считается 1); продажа сделки = сумма позиций.
3. Печать/фреза берутся со сделки read-only; маржа считается на уровне сделки.
4. Оклейка редактируется в строке сделки, PATCH в `opportunity.rashodOkleyka`, Tab/Enter/Esc работают, оптимистичные итоги пересчитываются.
5. Сегмент «Весь месяц / 1-я / 2-я половина» + splitDay корректно режут период; записи ЗП грузятся точным совпадением периода.
6. Панель: добавление/редактирование/удаление людей; Фонд/Раскидано/Остаток корректны; в month-режиме две группы.
7. «Из прошлого периода» копирует людей с обнулёнными часами; автоставка по имени работает.
8. «Распределить остаток» заполняет только пустые/нулевые оклейки пропорционально продаже с подтверждением; сумма распределённого = остатку (± округление).
9. Подсказка «по продаже ≈ N ₽» видна при редактировании оклейки.
10. Excel — сделко-уровневые строки по текущему фильтру.
11. «Реализация», `rashodItogo`, `rashodVyezdnayaKomanda` не затронуты.
12. Vitest-сьюты salary зелёные.
